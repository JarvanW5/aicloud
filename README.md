# AICloud 大模型工具箱和社区交流平台

AI Cloud 大模型工具箱和社区交流平台，是一个一键式生成所有大模型结果的项目，目前支持调用国内外几款顶尖大模型（例如Openai的ChatGPT，阿里巴巴的通义大模型，讯飞的星火大模型，百度的文心一言大模型，字节的豆包大模型）聊天对话功能以及图片生成等功能，并且也支持近百种大模型调用（使用Ollama来部署本地大模型），还有社区交流和评论等功能。

## 项目亮点

1. 使用并发编程技术保证项目的执行效率，使用线程编排保证任务的正常执行。
2. 使用分布式锁保证大模型接口调用的安全性和稳定性，其中分布式锁实现了锁重入、锁自动续期、锁误删、单点分布锁故障等问题。
3. 项目在关键操作上添加了幂等性判断（关键实现技术为自定义注解+Redis 实现），保证系统的稳定性和安全性。
4. 使用多种设计模式完成项目开发，例如，责任链设计模式保证项目的安全、使用工厂模式来提成程序执行效率、使用建造者模式实现创建并赋值对象、使用生产者和消费者模式实现异步通信和模块解耦、观察者模式实现数据实时读取、使用懒汉模式实现资源的充分利用等。
5. 使用 MQ 实现系统的削峰填谷，以及保证整个程序流程执行的完整性。
6. 使用 Canal 通过监控 MySQL 的 Binlog 解决数据库和 Redis 的数据一致性问题。
7. 项目中使用了分库分表技术增加数据库的并发处理性能。
8. 高并发场景稳定性设计，例如自定义拒绝策略保证任务不丢失和及时通知到负责人进行手工补偿处理。
9. 支持云端大模型和本地大模型的调用，近百种大模型的支持和调用。
10. 使用最新的 JDK 长期支持版和最新版的 Spring Boot 框架和组件完成程序的开发。
11. AI 方向项目，热门有发展前景。

## 项目开发过程中的问题以及解决方案

1. 问题：对接各家 AI 大模型，接口参差不齐，调用的时候官方文档提供的可能比较模糊，导致调用出错。解决方案：通过查看官方提供的 DEMO 案例和源码分析出问题，然后修改调用代码从而解决问题。
2. 问题：使用缓存（Redis）提升程序性能时，导致数据不一致的问题。解决方案：使用 Canal 通过监控 MySQL 的 Binlog 解决数据库和 Redis 的数据一致性问题。
3. 问题：使用 Kafka 手动确认消费消息时，只考虑正常的点赞请求，导致重复点赞消息未确认，重复调用、消息积压的问题。解决方案：改正业务代码，业务流程执行完之后，无论正常消费，还是重复点赞都会确认 Kafka 消息，保证消息不积压和及时消费。
